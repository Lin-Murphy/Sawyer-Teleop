# 运动设计与不变约束

模块与线程见[架构](../ARCHITECTURE.md)，当前结果见[PLAN](../PLAN.md)，验收数值见[固定门槛](ROG_TRACKING_EXPERIMENT.md)。
本页描述当前设计，不保存逐轮调参流水账。

## 最小链路

A 将真实 Quest 位姿映射为机器人末端目标，经一个可关闭的位姿滤波器和单个异步 IK 得到关节目标。
B 接收最新有效目标，用一层协调轨迹连续更新七轴参考；旧目标不排队等待到位。
实际反馈、参考轨迹、IK 目标和原始手柄四类数据分别保留。

- A IK 使用上一有效解作种子；失败暂停，不自动更换求解路径或补造可用结果。
- B 从当前参考位置/速度衔接，使用原源采样间隔估计目标速度，避免逐点停到零速。
- 参考速度/加速度和模型关节限位受约束，不保证实际速度绝不超调、末端严格直线或跃度连续。
- Standard 和 Fast follow 使用同一 coordinated 算法；差异只是已有仿真加速度字段。
- Gazebo 用 q/dq/ddq 的 TRAJECTORY_MODE，原镜像已有动力学前馈；真机保留 POSITION_MODE。
  这不是新实现的力控或阻抗，也不表示采用了 DROID 的执行控制器。

## 两种停止

**停手但仍握持**：继续跟踪近似静止的目标，按原窗口衡量收敛、残差与过冲。

**松手、断连或失效**：取消当前 generation、目标槽和轨迹；只能在反馈有效时提交保持。
不能为了平顺继续执行已失效目标。软件取消成功不等于物理瞬间静止。

## 问题按层拆开

| 现象 | 比较 |
| --- | --- |
| 输入/映射有误 | 原手柄与映射目标 |
| IK/轨迹绕路或滞后 | 映射目标、IK 目标、B 参考 |
| 实际回摆或跟不上 | B 参考与真实反馈 |
| 意外暂停 | 原输入、原引用、时钟不确定度、调度间隔与原因码 |
| 录制失败 | 写盘队列与相机负载；不以调参掩盖 |

时效的重复检查有明确边界：输入接收、缓存复用、IK 派发、B 接收和每次提交都重新验证。
新输入或新反馈不刷新旧结果的寿命；时钟映射变化不改写旧输入身份。
Gazebo 多话题乱序处理最多暂存一条 joint/pose，并保留首次到达年龄，不续期。

## 保持简单

用户已认可两项手感，当前不再增加预测、零空间策略、多层滤波、积分补偿或复杂 IK。
只有现有证据指出具体问题时，才做单因素修复和对应回归。失败分支、缺失服务和原数据不删除。
早期 cubic/responsive/S0/前馈/负载实验详见历史设计
与历史计划，不能把归档候选当成可切换的发布选项。
